# Product Challenge

- **Cursor repetition is ambiguous.** The edge cases reject a “repeated cursor,” while FR-007 explicitly permits replaying the same cursor. Presumably the former means duplicate `cursor` query parameters in one request, but that is not testable as written. **Recommendation:** architect should distinguish cross-request replay (valid) from multiple occurrences in one query (400 `invalid_cursor`) and test both.

- **Mutation semantics cover insertions but not changed/deleted anchors.** The spec explains inserts on either side of an anchor, yet display-name edits can move a player across the boundary and deletion can remove the anchor. Keyset traversal can then omit or repeat records without violating the narrow “unchanged catalog” guarantee, while clients may infer stronger stability from “stable cursor.” **Recommendation:** document that ordering-key updates/deletes may cause gaps or duplicates across pages, ensure decoding does not require the anchor row to still exist, and test continuation after anchor deletion. Snapshot pagination is a credible alternative, but its state/cost is disproportionate to CP1.

- **Public field types and nullability are missing.** Exact field names are specified, but the JSON types/formats for all IDs, `catalog_identity`, years, codes, and names are not. This leaves “exact response shape” and malformed `player_id` only partly testable and risks exposing an import key through `catalog_identity`. **Recommendation:** trace every field to TASK-005, define serialization and nullability in the plan, and confirm `catalog_identity` is a stable, safe public domain identifier rather than a provider identifier. Escalate to product only if that trace fails.

- **Opaque does not establish cursor integrity or scope.** Tampering must be rejected and foreign cursors rejected, but “foreign” is undefined (another endpoint, deployment, catalog, or authenticated user). **Recommendation:** scope cursors to this endpoint and contract version, require integrity protection, avoid embedding sensitive values in plaintext, and state whether valid cursors are intentionally transferable between authenticated users. Actor binding adds little protection for non-user-specific catalog data and complicates sharing/replay.

- **SC-008 is not a reproducible gate.** “Normal local operating conditions” omits hardware floor, dataset distribution, warm-up, concurrency, request count, and measurement boundary. A 95th-percentile claim cannot be independently verified consistently, and CP1 defines no latency SLA. **Recommendation:** either define a deterministic benchmark protocol with separate first-page, continuation, and detail results, or record SC-008 as non-gating diagnostic evidence; do not claim capacity from an ad hoc local run.
