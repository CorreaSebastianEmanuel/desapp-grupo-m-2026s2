# Independent product challenge — TASK-012

1. **The latency criterion lacks a reproducible acceptance gate.** SC-006 requires 95% of requests against 100,000 players to finish within two seconds under “normal local operating conditions,” but specifies neither the machine and database conditions nor the filter selectivity, page size, concurrency, and measurement method. `docs/CHECKPOINTS.md` names a catalog for CP1 but no quantitative CP1 latency gate. **Recommendation:** The architect should define a repeatable dataset, request mix, environment, and measurement protocol before claiming SC-006 passes. Preserve the stated threshold unless a product owner explicitly changes it; report any inability to meet it rather than silently narrowing the test.

2. **Backward cursor compatibility needs a genuine migration test.** FR-009 promises that existing unfiltered TASK-011 cursors remain usable. A test using a cursor produced by the new implementation would miss a format or signature incompatibility. **Recommendation:** Keep a pre-change unfiltered cursor fixture and verify that it continues unfiltered, rejects added filters, and follows the existing cursor lifetime rules. A new filtered cursor format may be needed, but its encoding is an architecture choice.

3. **Filter ID discovery is an implicit client prerequisite.** FR-002 uses internal IDs in player representations, while SC-007 says a user can narrow by any dimension. A client with no known IDs must first traverse the catalog to discover selectable teams and positions; the spec excludes new discovery and UI behavior (FR-016). **Recommendation:** State this API prerequisite in the contract or usage guidance and test filtering with IDs obtained from real list responses. Do not add enumeration endpoints under TASK-012 without a separate scope decision.
