# Product challenge — TASK-020

- **Historical integrity extends beyond deleting referenced records.** Evidence: spec FR-003, FR-008 and US2.3/5/6 require season consistency and stable historical relationships; ADR-0002 permits current affiliation changes. A surviving foreign key does not prevent a referenced team/player changing season, or a concurrent catalog change invalidating a previously validated submission. Recommendation: architecture must identify which catalog mutations can invalidate stored facts and protect those invariants across supported writes, including concurrent submissions. Prefer narrowly targeted constraints/transaction coordination over freezing whole catalog records, which would contradict authorized transfers. Include a race test and a referenced-record mutation test; preserve allowed current team/position changes.

- **Kickoff precision can silently alter retained facts and interval membership.** Evidence: US1.1 promises the same instant; FR-010/011 require inclusive bounds and equivalent-offset behavior, but supported timestamp precision is unspecified. Truncating a supplied fractional instant can move a performance onto a boundary and create artificial ordering ties. Recommendation: document one lossless supported precision for storage, input and queries; reject unsupported precision rather than silently rounding. Test fractional instants immediately inside/outside a bound and equivalent offsets. Preserving arbitrary precision is an alternative with greater storage/query complexity; the constitution supports a conservative, documented validation boundary without a human check.

- **Append-only inputs alone do not guarantee reproducible historical quotes.** Evidence: PRODUCT invariant 7 requires reproducibility; spec FR-008 prohibits replacement, while FR-010/011 allow histories selected by kickoff. A newly inserted performance for an old kickoff changes a repeated historical interval query despite every existing fact remaining immutable. Recommendation: flag this dependency explicitly for TASK-022 and subsequent quote design. Future quotes should retain the exact input membership or an equivalent immutable input snapshot/version. A cutoff based on when facts became available is an alternative, but requires durable availability semantics. Do not add provenance, quote snapshots or backfill policy to this task: FR-013 excludes them. CP2 acceptance must demonstrate reproducibility under late arrivals rather than treating this model's immutability tests as sufficient evidence.
