# Validation Guide — TASK-020

Run from repository root with the pinned toolchain and installed Mix dependencies. Start existing local PostgreSQL/Redis with `sh scripts/local_services.sh start` (or the repository's already provisioned services); configure credentials through environment, never manifest arguments. The application test database guard must remain enabled. No provider, HTTP server, user or seed command is needed.

1. `sh scripts/check_toolchain.sh`
2. `MIX_ENV=test mix test.prepare` creates/prepares only the guarded test database and applies migrations.
3. `MIX_ENV=test mix infrastructure.verify` must report both PostgreSQL and Redis OK; missing services fail rather than skip. Redis is infrastructure, not a statistics dependency.
4. Implement tests before behavior following tasks.md; run failing focused tests to prove the intended assertion before coding. Use contracts/statistics-context.md for calls/errors and data-model.md for rules.
5. Once implementation/source changes are final, execute every manifest check using `python3 scripts/agentflow_check.py CHECK_ID`, in manifest order. The manifest is the command authority: toolchain, prepare, preflight, format, compile, input, storage, integrity, concurrency, history, feature_scope, unit_profile, integration_profile, integration_coverage, coverage, regression, diff (plus catalog_concurrency after concurrency). Inspect bounded excerpts only for failures. New source changes require fresh receipts for every check before readiness.
6. `python3 scripts/workflow_artifact_probe.py develop --readiness` must pass after implementation and developer tasks are marked complete; QA/review alone stay deferred. Never create successful receipts manually.

Expected scenarios: store a completed match and two independent performances with all counts, a zero and unknown; repeat across five leagues/two seasons. Duplicate identity/pair variants reject, unrelated season reuse succeeds. A batch with one invalid entry persists none. Direct mutations/deletions and catalog key mutations fail without loss, while same-season current transfers work. Real connection races have exactly one winner and preserve relational integrity. Their focused command uses the dedicated statistics_concurrency partition; full-suite/profile runs invoke its asserting driver, keeping committed fixtures out of the normal Sandbox database. Histories return exact player membership, kickoff/identity order, inclusive bounds and preserved historical affiliation. Equivalent offsets and one-microsecond boundaries retain the same chronology. Reads succeed repeatedly without a provider.

Separate profiles require existing Node 24/Playwright/browser prerequisites for repository integration regressions; no silent skip. Existing CP1 coverage remains informational and scoped by its accepted inventory, not proof of full CP2 coverage. Do not change that denominator in this feature.

QA independently executes the same commands directly, challenges each scenario/mapping and writes its own report; developer receipts do not replace QA. There is no affected HTTP endpoint, hence no feature HTTP runtime check. A new endpoint would exceed FR-013. Quote reproducibility under late input arrival is explicitly reserved for TASK-022 and quote acceptance.
