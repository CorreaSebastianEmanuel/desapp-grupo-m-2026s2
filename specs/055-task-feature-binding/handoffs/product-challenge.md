# Product challenge

1. **An existing completion path is absent from the acceptance matrix.** `agentflow:98–105` marks merged dependencies `done` without resolving their features or checking reports. FR-006 covers *all* transitions to `done`, but the named consumer matrix could leave this bypass intact. Architect: include dependency reconciliation in the shared completion guard and test missing, failed, and foreign-feature reports. Preserve its existing human-merge prerequisite and dependency-only mutation boundary; do not add new reconciliation behavior.

2. **Legacy reconciliation can confuse branch syntax with ownership.** `scripts/reconcile_merged_task.py:19–24` accepts any valid slug after the task number, whereas `agentflow:53–56` derives the full delivery branch from task identity and title. With FR-004's declaration-free fallback, a merged `017-unrelated` could otherwise complete TASK-017. Architect: require exact expected branch identity before compatibility resolution, including metadata-only associations. Test a syntactically valid wrong suffix and a mismatch between filename and frontmatter ID. Numeric-prefix validation alone cannot satisfy FR-005.

3. **Directory containment does not establish evidence containment.** FR-005 constrains the selected directory, but does not explicitly constrain symlinked `spec.md`, `qa-report.md`, or `review-report.md`. Existing report readers follow symlinks (`agentflow:500–508`; reconciliation script:55–58), allowing another feature's passing evidence to appear under the selected directory. Architect: validate resolved canonical and report paths remain within the selected feature before reading them; reject escapes with actionable errors and no state change. Allowing contained symlinks is a reversible compatibility choice; rejecting every symlink is simpler but potentially stricter than necessary. Prefer containment checks, with external and foreign-feature escape regressions.

4. **Invalid unrelated specifications could become a repository-wide blocker.** FR-004 says invalid explicit information causes refusal, without defining whether that applies to unrelated scan results. Architect: document candidate-scoped failure rules: reject malformed or contradictory ownership information relevant to the requested task, without requiring every historical specification to be repaired. A global validation policy offers stronger repository hygiene but expands this task's scope and could block legitimate publication. Test a valid association beside an unrelated malformed declaration, while retaining duplicate expected-branch rejection.

5. **Idempotence needs an explicit validation boundary.** FR-005 requires identity and association validation; FR-007 promises an unchanged successful no-op for an already completed task. Current reconciliation returns before feature/report checks (`scripts/reconcile_merged_task.py:46–48`). Architect: validate unique task identity and the supplied full branch before the no-op, but do not require surviving feature reports when no completion transition occurs. This preserves retry behavior while preventing the wrong task from being acknowledged. Test both an already-done task with absent reports and an already-done task requested through the wrong branch.
