# Existing consumer boundary and source transport port

Consumers continue calling `FootballMarket.Providers.catalog(request, options)` and `performances(request, options)` using the merged TASK-016 request/result/error types. See [TASK-016 specification](../../016-external-football-provider-contract/spec.md) and ADR-0013. This feature adds no HTTP route, caller operation, local schema or provider-specific consumer branch.

`provider: {FootballMarket.Providers.Scraping, state}` implements `provider_label/0` (`fotmob`) and `read(request, context, state)`. Fixtures use the same source label plus required fixture_id; attribution does not imply live readiness. State provides a transport and current assessment reader, not additional football inputs. Runner supplies positions, runtime and deadline_us. Candidate maps match existing Validator input exactly; final results are never built by bypassing Validator.

Internal transport `fetch(portion, context, state)` returns either a source document/observation or an existing safe failure category. Portions are typed discovery, roster or match-detail keys with expected scope and IDs. Context includes the original absolute deadline, assessment revision and exact destination policy. No credential-bearing address is a returned field. No retry or implicit redirect. DisabledTransport always returns unsupported_capability without network calls, including when caller configuration claims enabled.

FixtureTransport loads safe source-shaped documents by stable ID, simulates elapsed time and admission events, rejects any non-fixture destination, and records request counts. It supports missing/refused portions, revision withdrawal/expiry between portions, destination rejection and simulated aggregate budget/concurrency exhaustion. Missing/inapplicable assessment is unsupported_capability before fetch; invalid caller input is rejected earlier by Providers. An observed source refusal is authentication_failed; 429 is rate_limited with only validated positive delay; temporary failures unavailable; documented missing scope not_found; malformed/ambiguous content invalid_response. Use existing Error templates.

No concrete live network transport is supplied. Before future activation, implement and review atomic shared admission across all callers, limits/cadence, revocation and cancellation, approved destinations, authentication handling and applicable retention. Nonconforming transport cannot become live-ready just because tests passed or config changed.

A successful source operation returns only a complete candidate for the exact requested scope. Missing portions cannot return earlier candidates. Final validation/publication must check assessment revision/time; deadline at equality wins over all other outcomes. Completed matches with explicitly published empty performances remain valid; absent collection/detail is incomplete. The performance directory is never used as a catalog.
