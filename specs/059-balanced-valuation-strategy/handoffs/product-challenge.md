# Independent product challenge — TASK-023

1. **CP2 readiness needs calibration ownership.** The spec's Assumptions deliberately provide no production preset, while TASK-022 Feedback 1 assigns production references and weights to TASK-023/024. `docs/CHECKPOINTS.md` retains configurable valuation, quotes and ranking for CP2. A mathematically correct module alone cannot establish that those consumers have meaningful effective rules. **Recommendation:** explicitly surface this delivery dependency in the architecture handoff: TASK-025/026 integration must obtain and retain an intentional configuration before demonstrating market behavior. Do not imply fixture values satisfy calibration. Alternatives are operator-supplied settings, which preserve the current scope but require integration evidence, or a justified built-in preset, which adds a product calibration decision. Prefer operator-supplied settings under the current spec; there is no evidence supporting numerical defaults.

2. **The large-number example does not establish independence from decimal precision.** US3 scenario 4 tests large integer cancellation, but FR-003/007 also admit fractional exact weights without an arbitrary ceiling. Widely separated Decimal exponents, equivalent noncanonical Decimal representations and a residual just below/at/above a signed rounding tie can expose truncation or enormous intermediate scaling that the integer example misses. **Recommendation:** make these adversarial cases part of architectural arithmetic validation and durable public-workflow tests, with independently calculated expected results. Reuse exact coefficient/exponent operations and avoid unnecessary scaling of zero contributions. Fixed ambient precision is a simpler alternative but contradicts the approved arithmetic contract; a numeric input ceiling would change acceptance behavior and must not be introduced as an internal optimization. This is a test-design gap, not evidence of an existing implementation defect.

3. **Broad malformed-input wording needs concrete regression evidence.** US2 scenario 4 and the Edge Cases promise ordinary failures, but do not enumerate the structures that broke the completed dependency. TASK-022 Feedback 2/3 identifies improper lists in nested configuration and malformed traversal through public entrypoints; its contract also rejects malformed Decimal fields and arbitrary string-to-atom conversion. A new weights validator could bypass those protections before the common engine checks them. **Recommendation:** carry those concrete failure shapes into the balanced strategy's tracked tests, including malformed weights containers, improper nested tails, corrupted Decimal fields and unknown string keys. Check safe no-score failures through evaluation/scoring and mismatched replay configuration, without broad exception rescue. Implementing only happy-path metric membership validation leaves a known class of requirement failures uncovered.
