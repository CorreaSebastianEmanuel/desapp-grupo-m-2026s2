# Product challenge — TASK-046

1. **Sign-out failure must not look like confirmed invalidation.** FR-004 requires replay prevention and termination of connected tabs; FR-005 requires safe retry when authority validation is unavailable. Neither explicitly describes failure while ending the session. Clearing the current page/cookie can leave copied authority and other tabs usable. Recommend acknowledging successful sign-out only after authoritative invalidation; on failure, conceal local private content and offer retry without claiming the session ended. A purely local cookie deletion is simpler but cannot satisfy FR-004. Architecture should define the failure boundary and QA should inject invalidation failure, then attempt replay and access from the second tab.

2. **Session replacement needs the same isolation discipline as sign-out.** FR-002 replaces pre-login authority, while Story 3 tests account switching only after explicit sign-out. A second tab can retain a sign-in form opened before the first tab authenticates; submitting it can replace browser authority while an existing socket still represents the previous account. Recommend validating the current session at submission, retiring any displaced authenticated session before establishing replacement, and terminating its connected workspaces. Redirecting an already-authenticated submission to its existing workspace is also consistent with Story 1 scenario 4 and avoids replacement entirely. Prefer that simpler behavior; test the stale-form case with two accounts. Do not leave mixed-account sockets attached to one browser session.

3. **Separate authorization deadlines from display convergence.** FR-003 and SC-002 require authorization to end exactly at expiry, but allow two seconds for connected content removal; the edge cases explicitly defer disconnected-tab clearing until communication resumes. Recommend testing these as separate properties: deny protected work at the exact boundary, independently verify connected-tab clearing within the stated tolerance, and clear stale content before reconnect recovery. Do not represent offline erasure as guaranteed or make scheduler timing the source of authorization truth.

4. **Browser evidence is essential despite placeholder destinations.** FR-012/015 and SC-004 concern browser history, multiple tabs and private-content removal. Server-rendered assertions alone cannot demonstrate these properties. Recommend a minimal real-browser acceptance journey covering history restoration after logout/account switching, second-tab termination, expiry and reconnect, using account email as the private-state sentinel. TASK-063 owns broader profile separation (`docs/CHECKPOINTS.md`); this task still needs its explicitly required browser evidence. Keep charts and order behavior outside this verification scope.
