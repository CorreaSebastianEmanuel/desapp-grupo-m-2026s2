# Product challenge — TASK-019

1. **Lost completion at the attempt limit needs an explicit recovery design.** FR-011 counts interrupted attempts toward the finite budget; FR-013 forbids both fabricated success and silently lost recoverable work. US3.7 does not exercise publication followed by lost completion on the final attempt. TASK-018 FR-010/013 supplies durable acceptance evidence, but a new retrieval is not necessarily the same delivery. Recommend durable correlation sufficient to confirm the original acceptance without another provider invocation; test crashes before publication, after publication, and during completion bookkeeping on attempt three. If confirmation is unavailable, preserve an explicit exhausted/unconfirmed result and recovery guidance. An unconditional fourth ingestion attempt violates the budget; inferring success from current catalog contents lacks evidence.

2. **Blocked schedule occurrences can recreate the prohibited backlog storm.** The edge cases leave incompatible occurrences eligible, while FR-006 limits downtime catch-up to the latest occurrence. Neither explicitly exercises prolonged scope-busy operation spanning several due instants. Recommend applying latest-occurrence coalescing to overdue blocked work, retaining evidence of superseded occurrences rather than later executing each one. Contrast this with an occurrence already associated with an equivalent run: FR-006 makes it handled even if that run eventually fails; do not silently re-enqueue it. Test both cases across restart, failure, and disable/re-enable, including restart at an exact due boundary. A per-occurrence execution backlog would defeat the stated controlled-scheduling outcome.

3. **Stable configuration references do not guarantee stable effective inputs.** FR-005 protects accepted inputs against mutation, but the assumptions only require references to remain available after restart. A fixture or reconciliation configuration could change behind the same reference during retry-wait. Recommend persisting canonical non-secret input identity and checking referenced artifact identity before execution; fail safely on incompatible drift while revalidating current source-access restrictions. Snapshotting secret values or retaining obsolete authorization would breach the security boundary. Test changed fixture contents, changed reconciliation instructions, and revoked access without changing the reference.

4. **Offline evidence must demonstrate durable recovery, not merely repeated function calls.** FR-016 and SC-005 require restart/concurrency evidence, while the product handoff correctly warns against queue uniqueness as proof. Recommend database-backed competing admissions and worker/runtime restart tests with controlled time, including persisted retry deadlines and attempt budgets. Keep assertions independent of implementation-generated expectations. This supports TASK-019 acceptance; it does not establish the actual browser E2E profile or complete the charts/conditional-orders obligations in docs/CHECKPOINTS.md. Avoid expanding this infrastructure task to deliver those downstream features.
