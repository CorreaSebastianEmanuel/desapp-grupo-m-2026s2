# Implementation validation guide

This is the future implementation/QA run guide, not evidence that checks have passed during architecture. New helper/test paths are created by tasks.md. No application HTTP interface changes; service preflight still applies.

1. Install the existing CI toolchain (Elixir 1.20.3, OTP 29.0.6, Node 24, Python 3, Ruby with YAML, Git, Docker Compose). Start pinned PostgreSQL/Redis via `scripts/local_services.sh start`, then `scripts/local_services.sh ready`. Never reset volumes. Use existing local environment configuration; do not print credentials.
2. Prepare dependencies using CI commands: `mix local.hex --if-missing --force`, `mix local.rebar --if-missing --force`, `mix deps.get --locked`, `MIX_ENV=test mix deps.compile`, `npm ci --prefix tools/openapi`, `tools/openapi/node_modules/.bin/playwright-core install --with-deps --only-shell chromium`. These are setup, not proof of test success.
3. While implementing, run each story's named Python tests with `python3 -m unittest test.scripts.agentflow_ci_check_test` (substitute the specific module). Write failing behavior fixtures before changing implementation. Existing tests remain included in final discovery. Use fixture repositories to test malformed/empty manifests, legacy resume, wrong versions, missing services, missing pointer, tampering and retry stops; never damage live state or invoke a paid model.
4. After all edits, execute verification.json check IDs through `python3 scripts/agentflow_check.py CHECK_ID --reuse` in manifest order. The preflight is non-reusable. The CI collection runs once through `clean-tests` in a disposable candidate checkout with no .specify/feature.json; do not additionally run `mix test`, separate full profiles or coverage_report.sh. Python discovery must use `*_test.py`, assert a nonzero count and propagate errors. Full stdout stays ignored locally.
5. Check `python3 scripts/workflow_artifact_probe.py plan --readiness`, `python3 scripts/workflow_artifact_probe.py tasks --readiness`, then after all implementation/check tasks are complete `python3 scripts/workflow_artifact_probe.py develop --readiness`. No local output, stale hashes, failed preflight, missing artifact or unchecked implementation task may pass. Two unchanged-input failures stop; record cause/time/evidence and repair relevant inputs before continuing.
6. QA starts independently and runs each applicable manifest check with `--stage qa` and no reuse, then writes qa-report.md and concise handoff. Final review examines fresh QA and runs targeted checks for uncovered risks, writes review-report.md and handoff. Both reports must end exactly in `Verdict: PASS` for publication. Developer test fixtures may simulate this lifecycle, but cannot supply this feature's actual independent verdicts.
7. After both reports, Agentflow calls `python3 scripts/agentflow_evidence.py finalize TASK-064` and validates the compact evidence-summary.json without rerunning whole profiles. A fixture second checkout can understand that summary but must fail workspace readiness until its own checks run. Source/design edits after checks require re-verification; exact report-only output finalization does not. See ADR-0026 and data-model.md.

Expected evidence: current local schema-2 receipts with environment/discovery assertions, no new versioned attempt files, a bounded final summary, all 32 FR/SC requirement IDs covered, preserved historical files, and independent PASS reports. docs/AGENTFLOW_PILOT.md is a next-task observation protocol only. TASK-064 launches no second task or paid experiment and claims no token savings. Approved stage assignment is implemented here; deterministic launcher fixtures verify it without a live model call.

Model validation during implementation: run `python3 -m unittest test.scripts.agentflow_models_test` for all six defaults, partial per-field overrides, malformed/unsupported pairs, child rejection/spawn failures and saved/adopted/legacy/frozen resumes. `./agentflow start TASK-ID --dry-run --stage-model develop=gpt-6.1-sol --stage-effort develop=medium` must show only development changed, with CLI provenance and zero launches. Use disposable fixture tasks for `resume --dry-run` and `resume --adopt-models`; never adopt or mutate the active frozen run as a test. A rejected child must yield exactly one captured invocation, a visible failed attempt and nonzero stage outcome.
