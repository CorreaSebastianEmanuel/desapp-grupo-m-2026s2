# Product challenge — TASK-063

1. **Inventory completeness needs an independent source of truth.** FR-003 and SC-001 require every test to be assigned once and detect omitted tests, but “expected” inventory is not defined beyond a declared/controlled inventory. If expected inventory is generated from the same test discovery being checked, omitted tests can disappear from both sides and pass. Recommend the plan name an independently maintained assignment source (for example, profile metadata plus a discovery-vs-manifest completeness check), define how additions are required to enter it, and demonstrate an omitted-test negative case. Keep the mechanism an implementation choice.

2. **The CP2 evidence gate is not actually required by the acceptance criteria.** The checkpoint calls separate actual E2E a remaining core requirement, while FR-013 preserves existing CI categories and SC-006 only checks they are not weakened. A plan could therefore leave the new E2E profile optional/local and still satisfy the written criteria. Recommend require a CI invocation/report for the E2E profile, with explicit prerequisites and a visible failure when unavailable; if it cannot run on every CI environment, specify the required gate and its supported execution environment. This adds evidence for the checkpoint without changing existing quality contracts.

3. **The async synchronization success condition is under-bounded.** “Eventually records the terminal result” (US3, scenario 1) has no completion deadline or timeout outcome; a hung worker can make the E2E run hang rather than fail as FR-010 intends. Recommend a bounded wait and actionable timeout diagnostic, using the existing worker/run contract for terminal success/failure states. Do not invent new synchronization behavior.

Evidence: docs/CHECKPOINTS.md requires actual E2E profiles for CP2; TASK-063 outcome preserves CI quality checks; feedback/TASK-063 bounds product scenarios to implemented TASK-019 and TASK-046 behavior. No chart/order behavior is reopened.
