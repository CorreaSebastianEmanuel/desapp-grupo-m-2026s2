# Reproduce TASK-067 evidence

This is an implementation validation guide; the new CLI and tests are planned artifacts, not implemented by architecture.

1. Use the pinned versions from `.tool-versions`, existing locked Mix/Node dependencies and installed Chromium. Follow `docs/TEST_PROFILES.md` for configured PostgreSQL/Redis and invocation-owned Docker prerequisites. Choose a safe test database partition with existing environment configuration; never reset shared or historical data. Use `ERL_FLAGS='+S 4:4'` where required by the local environment.
2. During implementation, first write and run the new focused fixtures: `python3 -m unittest test.scripts.application_coverage_test`; `MIX_ENV=test mix test test/ci/application_coverage_native_test.exs test/ci/application_coverage_contract_test.exs`. Observe meaningful failures before implementing. These targeted development cycles are not an extra final full-profile execution.
3. Review new case assignments using `python3 scripts/test_inventory.py update --profile unit` and, for service-dependent native cases, `--profile integration`, then `python3 scripts/test_inventory.py check`. Update the TASK-065 exact inventory for new tracked Elixir files using its existing reviewed procedure; new files must be reconciled before final capture. Source-control staging, if used by implementation to make new Elixir paths tracked, does not authorize committing or publishing.
4. Finish source, inventory, design and contributor-document edits. Execute every manifest check with `python3 scripts/agentflow_check.py CHECK_ID` in manifest order. The `application-report` check runs preflight itself, then exactly one audited unit/integration pair and publication assertions. Do not separately invoke those full profiles or historical CP1 coverage. `e2e` runs the existing E2E profile once, outside the measured denominator.
5. Inspect `cover/application/status.json`, the referenced immutable `report.json`, `report.html`, and `measurements.md`. Confirm matching run/snapshot/hash, included/excluded inventory union, no test/support measured lines, exact expected partitions, unique source-line totals and actual measured percentage. `python3 scripts/application_coverage.py validate` verifies these without rerunning profiles. A low percentage is a valid report.
6. Exercise controlled failures through the focused tests: missing/truncated/duplicate/wrong-profile/wrong-snapshot exports, missing integration committed partition, injected profile failure/interruption, inventory drift, malformed records and prior success followed by failure. Each must exit nonzero and leave no current complete report. Tests use temporary roots and fake child outcomes; native fidelity fixtures create real small exports without launching full profiles.

The implementation owner runs all checks before requesting QA. QA uses `python3 scripts/agentflow_check.py CHECK_ID --stage qa` without reuse and independently challenges mappings and publication. Review uses fresh QA evidence and targeted checks. After two unchanged-input failures, diagnose according to `docs/AGENT_VERIFICATION.md`; unavailable services are failures, not skipped acceptance. No current measured result exists at architecture time.

Coverage measures native executable source lines in the existing audited unit/integration BEAM invocations. It excludes tests/support, compile-only lines, JavaScript and independent nested BEAM/E2E execution. It does not prove correctness, complete business-scenario coverage or Sonar equivalence. Existing CP1/JS reports and hosted quality gates retain their separate ownership.
