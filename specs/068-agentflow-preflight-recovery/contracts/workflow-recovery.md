# Agentflow recovery contracts

## Read-only preflight

New interface: `python3 scripts/agentflow_preflight.py --stage STAGE --provider PROVIDER` (optional `--check CHECK_ID` for manifest prerequisites). Root is the current repository; task/feature use the existing resolver. The CLI constructs the same child context as launch, emits one safe JSON result to stdout, and exits 0 only for all applicable required prerequisites passing; 2 means failed/unknown/unavailable/configuration error. No log/journal creation, saved-state change or provider launch is allowed. Internal builder accepts planned launch arguments/assignment in memory and returns the exact context to Popen; this is not a shell command executor.

Authoritative built-in policy specifies bootstrap and per-stage inventories as described in plan.md. Optional per-check prerequisite objects have unique `id`, `kind`, `target`, `expected` and `recovery` fields. Kinds are `executable`, `setting`, `file`, `service`; target is a declared executable name/path, setting name, contained file or symbolic registered service. Expected is a registered condition/version/presence rule, never an arbitrary expression/command or literal credential. Service registry binds to existing read-only local readiness probes; extensions to probe kinds need architecture feedback. Unknown kind/service/condition, malformed field or unsafe path fails closed. Probes use the final child env/cwd and five-second bounded calls. Protected inputs/state hashes and fake service mutation counters prove evaluator purity.

Bootstrap probes Python 3, Git, Specify/provider executable resolution and readable launch/configuration inputs. Version compatibility for app checks references `scripts/check_toolchain.sh` and Node 24 in existing profile tooling; dependency probes inspect presence/locks without installs/builds. PostgreSQL/Redis checks use existing `scripts/local_services.sh ready` behavior. A service being down is unavailable, a version mismatch failed, inability to inspect safely unknown. Services are never started automatically. Optional non-app stages do not require application services. Never claim provider authentication from executable existence; if no safe local authentication probe exists, report that capability as unknown only where authentication is a declared prerequisite, without issuing paid/provider requests.

## Diagnostic

Safe object fields: `task`, `feature`, `stage`, `check` (nullable when unavailable), `category`, `cause`, `expected`, `observed`, `elapsed_ms`, `evidence`, `action`. Categories include prerequisite-missing/incompatible/unknown/unavailable, check-failed, interrupted, dependency-blocked, retry-limit, invalid-evidence/configuration. All text derives from an allowlisted message catalog; variable observations are non-secret type/status/version only. A failed combined CI profile pair reports its profile (`unit` or `integration`), failed command step (`prepare`, `tests`, `audit`, `cleanup`, `component`) and safe isolation partition when known, plus the allowlisted failure category. Evidence is a contained relative reference or null when no file was written. Unknown identity is explicit, never guessed. Credential fields, raw exception text and arbitrary check output never appear in console/journal/report diagnostics. Do not remove existing private full check outputs; summaries reference those protected files.

## Batch execution and reporting

New interface: `python3 scripts/agentflow_stage_checks.py --stage develop|qa|review` (optional development-only `--reuse`, and `--static-workers 1|2` defaulting to two). Reads active manifest, validates metadata, executes dependency-ready static groups with at most two workers, serializing all other checks and reporting in declaration order and reports all outcomes; exits 0 only when every required check passed with valid evidence. QA/review reject `--reuse`. Existing `agentflow_check.py ID [--stage STAGE] [--reuse]` remains compatible, with QA reuse refusal preserved. Same-stage check continuation requires explicit proven independence from dependency and potentially corrupted state. Unspecified independence blocks after a failure. Profile commands sharing test DB/build outputs are serialized and declared shared.

Provider wrappers carry a single stage attempt token, run preflight before provider Popen, finalize a non-PASS partial QA report on failure/interruption/missing required results, and preserve existing independent attestation validation. QA prompts instruct batch use before semantic acceptance. Development batching never writes an independent QA PASS. Reports end exactly `Verdict: FAIL` while incomplete; only independent QA can complete `Verdict: PASS`. Existing report word limits apply; retain full machine inventory locally rather than silently dropping rows. SIGINT/handled SIGTERM yields nonzero (130/143 respectively), running check interrupted and remaining checks accounted for. SIGKILL recovery yields a non-PASS report on next entry; no guarantee of a new report at the moment of abrupt termination.

## Retry and feedback compatibility

Stage budget is two failed full launched attempts per unchanged failing-input set. A failed attempt's retry scope is the set of failed checks plus their transitive dependency closure; each check contributes its own command/input identity and dependency edges. Changes only to independent checks do not reset that scope. A material change to a failed check or dependency input/edge makes another attempt eligible. Preflight refusals are not attempts. Nested individual check failures consume their own existing guard but only one enclosing stage failure. On a third unchanged full request, refuse before child launch with both safe failure references and accumulated elapsed time. Relevant input component changes are reported by path/code and digest, never contents. Run/session changes, report writes and unrelated edits do not reset. Running/interrupted attempts without a recorded trustworthy scope and older journal records are compared against the complete stage snapshot; do not infer a narrower failure scope. Malformed or unsupported stage history blocks.

The stage-attempt JSON journal has one persistent sibling lock file per workspace/feature/stage. A cross-process exclusive nonblocking lock protects the complete read/append/replace lifecycle and stage execution; a concurrent launcher receives a safe "stage already running" refusal before reading or changing the journal. POSIX uses `fcntl.flock`; platforms without `fcntl` use a compatible one-byte `msvcrt` lock. Lock files are not unlinked, avoiding inode replacement races. Abrupt process exit releases the OS lock; the next launcher can then recover a durable `running` attempt conservatively.

`agentflow feedback --impact ... [--stage ...] [--checks ...]` keeps existing syntax. Resolve all checks and earliest owner before feedback/state mutation; pending impact records a pending entry and prevents dependent work. Product repair includes product challenge; architecture/verification repairs regenerate applicable canonical artifacts. Implementation-only feedback preserves spec/plan bytes. Feedback 1 changes the repository cycle cap from 16 to three (absent-key default also three). Existing durable cycles count across resume/run IDs; a third repair is allowed, a fourth is refused before rewind/launch while preserving its feedback/evidence. Exhaustion recommends explicit task splitting for a human decision, never creates a reset automatically. Explicit future configured overrides require reviewed policy, not silent clamping. Per-check and full-stage budgets remain separately two failures.

## CI baseline and HTTP compatibility

`python3 scripts/agentflow_stage_checks.py --ci-parity` replaces the raw local baseline only. It validates exact CI wrapper/profile/env contract, matching active manifest obligation and both workflow copies, and executes `test/scripts/ci_unit_tests_test.sh` with isolated stub children. Exit 0 requires every assertion; failure is nonzero with safe repair guidance. It never runs real profiles, starts services, falls back to the native baseline or accepts parity as development evidence. Readiness still requires current receipts. CI source is read-only. Resume converts only the recognized legacy raw baseline in memory to this guard; unknown step/command shapes fail closed and snapshots stay unchanged.

`execution_class: "static"` requires registered exact argv (`plan-artifacts` or `ci-parity` commands), explicit isolation and no shared effects. At most two such ready checks overlap. Drain before serial checks; Mix/build/cache/services/behavioral subprocess suites/E2E/browser always serial in this feature. Validate malformed metadata before any child launch. Record monotonic duration/count/peak-worker measurements; compare controlled fixtures, not duplicate full profiles.

Vibecode is a documented procedure in `docs/WORKFLOW_SPEED.md`, with brief spec/rollback/risk/acceptance, mandatory preflight, focused tests, CI, proportionate independent QA/review PASS and human merge. It excludes financial, security, data-integrity, migration, external-interface and workflow/gate changes. Unknown impact uses full flow. No new executable lane selector is introduced; TASK-070 is excluded. Procedure tests assert examples/exclusions and preserved gates.

No HTTP endpoint is introduced or changed. Existing route detection and runtime assertion checks remain required for other features; adversarial tests must prove a route obligation cannot pass with unit-only receipts, a bare request or unavailable service.
