# Product challenge

1. **Feature identity is inconsistent.** `.specify/feature.json` binds this run to `specs/068-agentflow-preflight-recovery`, while the spec branch and input identify TASK-070; that directory prefix instead matches the separate Dialyzer assessment TASK-068. TASK-070's outcome and spec content agree, so this appears to be a binding/traceability defect, not a product-scope conflict. Confirm the exact TASK-070 identity and correct the binding through the owning workflow before later stages rely on path-derived IDs. No `backlog/feedback/TASK-070.md` exists.

2. **Preflight's contract is underspecified.** FR-001/003 require “applicable prerequisites” and an “expected condition” but do not say where the prerequisite inventory and compatibility rules come from. Also, service visibility can change between preflight and launch, so “same effective environment” alone does not ensure the checked context is the launched context. Define the authoritative prerequisite source and require launch to consume the checked environment/configuration snapshot (or report a changed snapshot and recheck). Keep genuinely transient availability results distinct from deterministic checks.

3. **The partial-report promise exceeds its interruption boundary.** User Story 2 and FR-005 promise a report when QA is interrupted, but do not distinguish a handled interruption from abrupt process/host termination. Recommend durable per-check outcomes and a finalizer for handled termination; state explicitly which abrupt failures cannot guarantee a newly written report. Test both supported interruption behavior and truthful recovery from an incomplete report.

4. **Retry and deduplication need auditable identity rules.** FR-007/SC-004 leave “material” input change and “full attempt” to interpretation; FR-009/SC-006 likewise do not define profile identity, evidence freshness, or how coverage maps to obligations. Recommend a dependency-scoped input fingerprint with changed components reported, a clear attempt boundary, and a verification-obligation map keyed by profile/configuration and source state. This prevents unrelated edits resetting retries or stale/partial evidence suppressing required work.

These are architecture/acceptance-definition gaps, not requests to expand the feature. Retain the documented two-failure policy and all separate CI, independent-QA, and HTTP obligations.
