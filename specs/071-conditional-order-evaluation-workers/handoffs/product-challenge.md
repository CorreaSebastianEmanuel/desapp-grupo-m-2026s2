# Product challenge

- **Conflicting-order determinism is underspecified.** FR-009 requires reproducible creation-time/order-ID ordering while also allowing bounded concurrency and disclaiming strict global priority. If two qualifying orders compete for the same scarce inventory or user balance, concurrent execution can still make the winner depend on lock/job scheduling. That changes which user receives a purchase. ADR-0017 sets the intended order but leaves enforcement to TASK-060. **Recommendation:** define determinism for orders that contend on the same player inventory or user balance: process them in creation-time then stable-ID order within that conflict set, while allowing concurrency across independent sets; add a concurrent scarce-resource scenario asserting the winner and invariants. If only invariant safety is intended, remove “reproducible ordering” and explicitly accept scheduling-dependent outcomes.
- **Notification strength conflicts between criteria.** FR-010 says a post-commit notification MUST be made available, while Story 3's scenario says connected views “may” be notified; the edge case permits lost notification. ADR-0017 calls for post-commit PubSub, and the product handoff treats it as a reload hint. **Recommendation:** specify best-effort post-commit PubSub signaling, with persisted order state as the sole guarantee; verify no signal precedes commit and reconnect/read recovers state, without making delivery an acceptance guarantee.
- **Quote validity crosses a domain boundary.** FR-003 and FR-012 rely on a “current valid quote,” but the acceptance criteria do not state how a quote is considered current/valid beyond absent, invalid, or nonpositive. **Recommendation:** bind evaluation to the existing quote domain's authoritative validity contract and name the data/decision point in the plan; test that boundary without creating a second definition in this feature.

Evidence: `spec.md` FR-003, FR-009, FR-010, FR-012; User Story 3 scenario 1; Edge Cases; `docs/adr/0017-cp2-charts-and-conditional-orders.md` ordering and notification guidance; `handoffs/product.md`.
